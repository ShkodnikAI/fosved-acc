# AGENTS.md — правила работы с fosved-acc

Читать первым, до любой задачи. Короткий список правил, перенесённый из практики FOSVED-office-v2, Metalogos и HUK.

## 1. Роли

| Роль | Кто | Делает | Никогда не делает |
|---|---|---|---|
| Владелец | ShkodnikAI | решает необратимое, идентичность проекта, юридическое; нажимает подтверждения | — |
| Аудитор | Claude в чате проекта «Аудит» | пишет наряды (issues), проверяет сделанное после мержа | пишет код фич, мержит |
| Исполнитель | агент-исполнитель | исполняет опубликованный наряд: ветка → PR → мерж при зелёном CI → отчёт в issue | создаёт или меняет наряды, мержит при красном или пропущенном CI, выдаёт косвенную проверку за прямую |

Сдано ≠ принято: мерж на зелёном CI — «сдано», «принято» — вердикт аудитора после проверки.

## 2. Код — источник правды

README, ТЗ и прошлые отчёты могут отставать от кода. Прежде чем действовать по описанию — проверь фактом: `grep`, запуск, лог. Документация Metalogos тоже может расходиться с поведением бинаря (пример: `cron_remove` возвращает Struct, а REFERENCE пишет Float — `docs/reports/probes-0.32.md`). Проверяет проба, не чтение.

## 3. Синхронизация перед любой работой

```bash
git fetch origin main --force
git log origin/main -1 --format='%H %ci %s'   # что реально пришло
git checkout -q origin/main                    # или rebase ветки
```

Работа по устаревшему чекауту — самая частая собственная ошибка в соседних проектах.

## 4. Контракт наряда

1. Наряд = issue → одна ветка → один PR. Без PR работа не сдана.
2. Каждая заявленная функция подтверждена реальным прогоном (`mlog run`/`serve`, `curl`, тест), вывод — в отчёте.
3. Мерж — только при зелёном CI на коммите мержа. Шаг CI, который «пропускается» без нужного секрета, обязан падать, а не зеленеть.
4. Частичная работа — не закрытие: комментарий «сделано / осталось / блокирует», issue остаётся открытым.
5. Отчёт называет допущения и нерешённое. Косвенная проверка называется косвенной.

## 5. Секреты

- В репозитории нет ни одного ключа, токена, пароля, значения переменной. `.env.example` — только имена.
- Паспорт сайта хранит имя переменной (`token_env = "SITE_TEGA_GITHUB_TOKEN"`), не значение.
- Секреты не выводятся в логи, ответы, issues, PR и отчёты. CI проверяет это gitleaks.

## 6. Правила Metalogos, которые здесь действуют

- Недоверенные данные (`query_param`, `http_get`, `read_file`, ответы моделей) не решают `if` без `redact(…, "all"|"hash_only")` — иначе `UNTRUSTED_DECISION`, сервер не стартует.
- `env()` в маршрутах `mlog serve` читается только из `METALOGOS_ENV_ALLOWLIST`.
- Значения секретов не уходят в `respond` (`PII_EGRESS_OUTPUT`).
- Необратимое в БД (`DELETE`/`DROP`/`UPDATE …`) — только `db_execute_with_grant` с ограниченным правом.
- `exec`/MCP закрыты по умолчанию; открывать только нарядом.
- В блоке `llm {}` у провайдеров нет собственной модели (проба B.9): маршрутизатор моделей — забота кода АСС.
