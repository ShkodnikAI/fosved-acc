# ADR-0003 — Движок serve: interpreter до исправления Metalogos-#1336

Статус: принято (исполнитель, наряд АСС-1.7 #24, 18.10.2026). Класс: bug/ops, приоритет P0.

## Контекст

Metalogos 0.32.0 (Metalogos-#1336): под `mlog serve` на движке по умолчанию (VM, ADR-0171) цикл `each` внутри тела `if` не исполняется молча. Проверено на бинаре v0.32.0 (sha256 `dd8164b747aa99cb953d3f7a29e084ba38d432df376aa2f05cfd2187e2bc59a2`):

| Движок | `if {each}` | `each {if}` |
|---|---|---|
| VM | 0 итераций | 3 |
| interpreter | 3 | 3 |

Проба исполнителя на том же бинаре (18.10.2026) подтверждает таблицу: маршрут `/probe` с `if {each x in [3 значения]}` вернул `if_each=0` на VM и `if_each=3` на `METALOGOS_SERVE_BACKEND=interpreter`.

В коде АСС такой конструкцией является `DutyHandleVerdicts` (`modules/duty/check.mlog`): `if … pending != "" { … each ln in lines2 { … } }` — повторная проверка упавших страниц и открытие инцидента. На VM они не выполняются: сбой подтверждается в БД проверок, но инцидент не открывается, Дежурный молчит при сбое сайта. Dockerfile движок не задавал (`grep -n SERVE_BACKEND Dockerfile` пуст) — на проде работал VM. Полигоны гоняются через `mlog run` (интерпретатор) и ошибку не видят. В FOSVED-office-v2 по той же причине движок закреплён в `entrypoint.sh` (`METALOGOS_SERVE_BACKEND=interpreter`).

## Решение

Движок serve закреплён на `interpreter`: `Dockerfile` задаёт `ENV METALOGOS_SERVE_BACKEND=interpreter` (в образе, не в списке env Render — переменная не конфигурация окружения, а часть образа). Код модулей не перестраивается (запрет наряда: лечение выбором движка, не обходом).

Контроль регресса — тест `tests/serve/duty_serve.sh` (АСС-1.7 A.2): сценарий 2 полигона Дежурного под настоящим `mlog serve app.mlog`. В CI шаг на `interpreter` — блокирующий; шаг на `METALOGOS_SERVE_BACKEND=vm` — информационный (`continue-on-error`), сейчас ожидаемо красный.

## Условие возврата на VM

Вернуть VM (снять `ENV METALOGOS_SERVE_BACKEND=interpreter` из Dockerfile, пометить ADR superseded) при выполнении обоих условий:

1. Вышел релиз Metalogos с исправлением Metalogos-#1336.
2. Информационный VM-шаг CI (`duty_serve.sh … vm`) стал зелёным на этом релизе — то есть тест A.2 проходит на VM.

До тех пор красный VM-шаг — рабочий сигнал: его позеленение означает, что исправление доступно. Список мест `each` внутри `if`/`else` в коде АСС (входные данные для проверки после исправления и для возврата на VM) — в отчёте наряда #24.
