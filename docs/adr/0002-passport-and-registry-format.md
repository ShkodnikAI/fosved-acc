# ADR-0002 — Формат паспорта и реестров

Статус: принято (исполнитель, наряд АСС-1.1, A.1; диспатч #10). Дата: 18.10.2026.

## 1. Формат — JSON, не TOML

В Metalogos 0.32.0 нет разбора TOML и есть JSON: `grep -o 'spec!("[a-z_]*' src/builtins/registry.rs` в Metalogos- @ `11c1740` находит `parse_json`, `json_get`, `json_validate`; `toml` отсутствует. Пример в ТЗ §5 на TOML был предложением; выбор формата ТЗ оставляет исполнителю. Файлы: паспорт и оба реестра — JSON (`python3 -m json.tool` — базовая проверка, валидатор — полная).

## 2. Секреты и персональные данные — только имена переменных окружения

В паспорт и реестры не попадают значения ключей, токенов и Telegram id — только имена env, например `approver_tg_env: "ACC_OWNER_TG_ID"` (AGENTS.md §5). Проверка встроена в валидатор паспорта (правило 7: значения `*_env` — `null` или `^[A-Z][A-Z0-9_]{2,63}$`) и в CI (gitleaks). Правило 8 валидатора дополнительно отклоняет ключи с именами `token|key|secret|password|api_key` на любой глубине, строки с префиксами секретов и значения из 6–12 цифр (похоже на Telegram id).

## 3. Пути

- паспорт сайта: `sites/<slug>/passport.json` (первый — `sites/tega/passport.json`);
- реестр моделей: `registry/models.json`;
- реестр источников: `registry/sources.json`.

Реестры общие для всего АСС, паспорт на них только ссылается по `id` (ТЗ §4.1, §5; ADR-0001 п. 6): правило 9 валидатора требует, чтобы каждый `id` из `sources` паспорта присутствовал в `registry/sources.json` со статусом `active`.

## Примечание (реализация валидатора, для следующих нарядов)

Текст паспорта приходит через `read_file` и недоверен. Решения `if` по недоверенным данным запрещены (`UNTRUSTED_DECISION`), причём недоверен и результат вызова паттерна с недоверенным аргументом (интерпроцедурный taint). Единственная форма решения, которую принимает `mlog check`, — inline-барьер в самом условии: `if redact(to_string(<предикат>), "hash_only") == redact(to_string(true), "hash_only") { … }` (детерминированность `redact(…, "hash_only")` на 0.32.0 подтверждена пробой; рецепт — наряд #546 FOSVED-office-v2, Metalogos-#1317). Недоверенные имена полей в сообщениях об ошибках проходят `redact(…, "all")`: обычные имена остаются без изменений, секретоподобные маскируются. То же правило понадобится любому коду АСС, решающему `if` по данным из `read_file`/`http_get`/`query_param`.
